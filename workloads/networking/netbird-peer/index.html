NetBird peer

k8s-routing-peer joins the NetBird mesh and routes the cluster LAN to Bifrost, so Traefik there can proxy public services to the Gateway. Mesh and Bifrost side: NetBird. Upstream docs.

Namespacenetbird (privileged PSA)
Sourcenetbird_peer.go
ExposureNone; it is the path for public traffic
Storagenetbird-config PVC, 100 Mi RWO, at /var/lib/netbird/
AuthNETBIRD_SETUP_KEY from OpenBao secret/netbird, first registration only

How it fits

Section titled “How it fits”
sequenceDiagram
  participant T as Traefik (Bifrost)
  participant A as bifrost-agent wt0
  participant P as netbird-peer-0 (any worker)
  participant G as Gateway 192.168.1.220
  T->>A: proxy to 192.168.1.220:80
  A->>P: WireGuard via relay
  P->>P: forward wt0 → pod eth0,<br/>MASQUERADE to pod IP
  P->>G: Cilium load-balances from the pod
  G-->>P: reply to the pod IP
  P-->>A: back through wt0

The StatefulSet has no nodeSelector; the pod runs on whichever worker schedules it. Because wt0 lives in the pod’s own network namespace, forwarded traffic leaves through the pod’s eth0 and Cilium load-balances it like any pod traffic, wherever the Gateway’s L2 lease is. With hostNetwork the peer depended on ARP for 192.168.1.220, which fails when the peer shares a node with the lease holder: a node cannot resolve the IP it announces itself. The MASQUERADE rule means backends see the pod IP, so no node needs a route to the NetBird overlay. No such route exists in talos.go; nodes get only a default route via the router.

The cluster subnet route is not set in code. Assign it in the NetBird UI: Network → Routes, network 192.168.1.0/24, routing peer k8s-routing-peer, distribution group All.

MASQUERADE initContainer

Section titled “MASQUERADE initContainer”

setup-iptables runs before the agent:

It matches “not back out wt0” rather than a NIC name. -C stops restarts from stacking duplicates. While the route’s Masquerade toggle is on in the NetBird UI, NetBird’s own NETBIRD-RT-NAT chain matches first and this rule counts 0 packets; it is the fallback if that toggle is ever turned off.

Never set NB_SKIP_SOCKET_MARK

The peer adds a host route for the management server via lo; socket fwmark lets its own traffic bypass it. Without the mark, management traffic loops into the tunnel, the relay never connects, and wt0 carries 0 bytes: every public service goes down. Details: NetBird.

Keep wt0 out of Cilium devices

wt0 is NOARP/POINTOPOINT; Cilium’s TC BPF drops its frames silently. cilium.go lists only ens18 and eth0. See Cilium.

Troubleshooting

Section titled “Troubleshooting”

Peer not connecting

Section titled “Peer not connecting”

Check logs, then that the management URL answers from the pod:

bifrost-agent shows Networks: -

Section titled “bifrost-agent shows Networks: -”

The route is missing in the NetBird UI or points at a stale peer. Delete old entries and assign it to the current k8s-routing-peer. Confirm on Bifrost:

504 from public services, tunnel up

Section titled “504 from public services, tunnel up”

Work from the peer’s node outward:

A 302 from the last command means the path works and the problem is in Traefik.

MASQUERADE rule not matching

Section titled “MASQUERADE rule not matching”

The ! -o wt0 rule to 192.168.1.0/24 should show a growing packet count. If it is missing, check that setup-iptables completed in kubectl describe pod.

wt0 shows 0 bytes

Section titled “wt0 shows 0 bytes”

NB_SKIP_SOCKET_MARK is set somewhere; remove it (see the danger aside).
