# Release v0.1.8

**Release Date:** 2026-10-29
**Branch:** `v0.1.8` → manifests at `v0.1.8-manifests`
**Status:** Released — merged to `main`, live on the cluster

## Overview

Three things: a config refactor, security hardening, and a move to latest
stable on every layer.

- **Config.** Every infra value and every version pin now lives in two files
  under `config/`, read by core, workloads and the justfile. Workloads share
  one helper package, `workloads/kit`. Synth output is unchanged except for PSA
  labels on privileged namespaces.
- **Security.** OpenBao no longer leaves a root token anywhere. Grafana is
  split into an admin org and a metrics-only public org. The VPS is key-only
  SSH with fail2ban. CI actions are pinned to SHAs, and every release gets an
  SBOM.
- **Versions.** Talos 1.14 with Kubernetes held at 1.36.5, Cilium
  1.18 → 1.20, Gateway API v1.6.3, Longhorn 1.13, n8n 2.x (a one-way database
  migration), Kubeflow 26.03, and the rest of the workload charts.

Kubernetes stays on 1.36 because Cilium 1.20 is not tested on 1.37.

## Changes

### Config and code (`bc5539a`, `17983e3`)

- `config/config.yml` holds the domain, LAN subnet, VIP, nodes, gateway, LB
  pool, OpenBao address and manifests branch. `config/versions.yaml` holds the
  chart, image, CRD and Talos pins. Both are embedded and typed, and
  `config/config.yml` replaces `core/config.yml`.
- `workloads/kit` has the namespace, HTTPRoute and OpenBao CSI secret helpers.
  Every chart uses it, and `workloads/main.go` is table-driven.
- The justfile reads `config/` with `yq` and no longer scrapes values out of
  Go source.
- The Talos GPU patch is layered on top of the worker patch. `talosctl`
  confirmed the rendered config is identical.
- Removed: `Pulumi.all.yaml`, `Dockerfile.archive`, dead stack config.
- `just hooks` installs gitleaks and trufflehog (pinned images) as pre-commit
  and pre-push hooks.
- CI pins actions to SHAs, sets least-privilege `permissions`, verifies
  download checksums, and runs a manifest Secret guard with a shrink-only
  allowlist. An SBOM workflow attaches `sbom.cdx.json` to the release.
  Renovate replaces Dependabot, and also tracks kustomize, Zola, syft, the
  Gateway API CRDs and Kubeflow's calver tags (`cffb72a`).
- The secret-scan hooks work from git worktrees and on `git commit -a`
  (`5d26781`, `594cfb5`). Before this, gitleaks scanned nothing in both cases.

### Security hardening (`28b950b`)

| Area | Change |
|------|--------|
| **OpenBao** | No root token on disk or in output. `just openbao-token` uses generate-root over an in-pod unix socket, and the token is revoked on exit. Stdout audit device. | **Grafana** | Two orgs. Org 1 (main) has VictoriaMetrics and VictoriaLogs; `grafana-admins` get Admin there. Org 2 "Public" has metrics only, and every SSO user lands in it as Viewer. Login form off. Org 2 is created by `just grafana-init`. |
| **Bifrost VPS** | Key-only SSH, fail2ban, unattended-upgrades. Traefik TLS 1.2+ and HSTS, ForwardAuth `trustForwardHeader` off. One env file per container. Unused firewall ports (3478/tcp, 5349, 50000-50500/udp) closed. |
| **Cluster** | A `ValidatingAdmissionPolicy` denies Service `externalIPs`, and Cilium `externalIPs` is off. Cilium `l2announcements` key casing fixed. NetBird peer MASQUERADE matches `! -o wt0` instead of naming the NIC. Headlamp's static token Secret is removed (`just headlamp-token`). Argo CD server is ClusterIP. ## Upgrade Procedure

Do these in order, and pass each step's gate before starting the next. The
runbooks referenced below are in `docs/content/upgrade-guide/index.md` on the
merged branch.

Argo CD keeps syncing `v0.1.7-manifests` until step 6. Until then, workload
changes on `v0.1.8` do not reach the cluster.

### 0. Checks and backups

```bash
kubectl get applications -n argocd               # all Synced/Healthy
just talos-health
just talos-versions                              # every node on 1.13.x
kubectl version                                  # record the running k8s version
kubectl get svc -A -o json | jq -r '.items[] | select(.spec.externalIPs) | .metadata.namespace+"/"+.metadata.name'   # must be empty: admission now denies them
```

- **n8n database.** n8n 2.x migrates the schema one way. The only way back is
  restoring this dump. Keep it off-cluster.
  ```bash
  primary=$(kubectl get pod -n n8n -l cnpg.io/cluster=n8n-pg,cnpg.io/instanceRole=primary -o name)
  kubectl exec -n n8n "$primary" -c postgres -- pg_dump -U postgres -d n8n -Fc > n8n-$(date +%F).dump
  ls -lh n8n-$(date +%F).dump
  ```
- **Longhorn.** Snapshot or back up every volume that is not re-downloadable:
  n8n-pg, Grafana, Harbor, OpenBao and the NetBird peer. Then confirm none of
  them is degraded or faulted.
- Confirm the OpenBao unseal key is in SOPS. Record a hash of the n8n
  encryption key; it must not change:
  ```bash
  kubectl get secret n8n-secrets -n n8n -o jsonpath='{.data.N8N_ENCRYPTION_KEY}' | base64 -d | shasum -a 256
  ```
- Confirm your SSH key logs in to the VPS. Step 9 turns password login off.

### 1. Talos 1.14.4

Use `talosctl` 1.14.1 or later (1.14.0 can hang the full timeout). The
`just` recipes use the default kubectl context, so select the cluster first.
Upgrade one node at a time, and gate each one on `just talos-health`, all
nodes Ready, etcd showing 3 members, and no degraded Longhorn volumes.

```bash
kubectl config use-context admin@talos-cluster
talosctl version --client --short              # 1.14.1 or later
kubectl get pod -n n8n n8n-pg-1 -o wide        # check before each worker: its node needs drain=false

just talos-upgrade 192.168.1.211        # control planes, one at a time
just talos-upgrade 192.168.1.212
just talos-upgrade 192.168.1.213
just talos-upgrade 192.168.1.223        # workers; prove Longhorn attaches on the first
just talos-upgrade 192.168.1.222
just talos-upgrade 192.168.1.221
just talos-upgrade 192.168.1.224 gpu false   # GPU worker last; new NVIDIA driver; drain=false for its PDBs
```

- **n8n-pg.** `n8n-pg` is a single-instance CNPG cluster and its PDB blocks
  the drain. It moves between workers, so on whichever node hosts `n8n-pg-1`
  run `just talos-upgrade <ip> base false`. A failed drain leaves the node
  cordoned with the new image installed: re-run with `drain=false`, then
  `kubectl uncordon <node>`.
- An undrained reboot can wait about 10 minutes on a Longhorn CSI unmount. It
  finishes by itself.
- `netbird-peer-0` runs on k8s-worker4, so public traffic drops while worker4
  reboots.
- Falco crashloops on every node from the first upgrade until step 6. See
  [Known Issues](#falco-0431-on-linux-61853).

After worker4, check that `talosctl -n 192.168.1.224 get extensions` lists
the `nvidia-*` extensions and that allocatable `nvidia.com/gpu` is 5.

Leave workload isolation (`SecurityProfileConfig`) off. It breaks Longhorn's
iSCSI frontend and `just longhorn-repair-iscsi`.

### 3. Gateway API CRDs v1.6.3, then Cilium in steps

**Pre-step.** Commit `5860400a` takes node IPs out of the LB pool, which
becomes .220 and .225-.230. Cilium 1.19 cuts a node off the LAN when an LB IP
equals its address, and before this Argo CD held .221 (k8s-worker1) and Ollama
.222 (k8s-worker2). Argo CD becomes ClusterIP in 3a. If Ollama still holds .222
after 3a, gate 4 fails: stop there. Its IP is pinned to `192.168.1.225` when
the v0.1.8 manifests sync in step 7; point `OLLAMA_API_BASE` in `~/.env` at
whatever `kubectl get svc -n ollama ollama` shows until then.

3a-3c are temporary edits to `config/versions.yaml` only. Argo CD and
cert-manager stay at the deployed versions (chart 10.3.2, image v3.5.1;
cert-manager v1.21.1) until step 4. Leave `config/config.yml` alone.

```bash

sed -i '' 's|version: 1.19.10}|version: 1.20.4}|' config/versions.yaml
```

Run `just core platform preview`, then `just core platform up`, for each.

Falco 9 drops the gRPC server and gRPC output, and the legacy eBPF probe.
The driver is already `modern_ebpf`, and `workloads/security/falco.go` no
longer sets the gRPC keys. Falcosidekick receives events over HTTP.

```bash
kubectl get ds -n falco falco -o jsonpath='{.spec.template.spec.containers[0].image}{"\n"}'   # falco:0.45.1
kubectl get pods -n falco -l app.kubernetes.io/name=falco      # all Running, restarts stable
kubectl logs -n falco ds/falco -c falco | grep -i signal_deliver   # empty
```

Gate: events arrive in Falcosidekick UI and VictoriaLogs.

Then set `argocd_manual_sync: false` and run `just core platform up` to turn
auto-sync back on.

### 9. Bifrost

```bash
just core hetzner preview   # no server replace (a user_data change replaces the VPS and its IP)
just core hetzner up
```

Authentik 2026.8 refuses to skip a minor (the newest `authentik_version_history`
row must be the previous minor). It honours forwarded headers only from
trusted proxy CIDRs; the default `172.16.0.0/12` covers Traefik. NetBird
server, proxy, agent and in-cluster peer must all be on 0.80.0. Gate: Gatus
all green, and `ip rule show | grep 7120` on the VPS.

### 10. Pulumi providers (cloudflare v6, proxmoxve v8)

For every stack, run preview before up. **Stop on any VM replace (proxmox)
or DNS record replace (cloudflare `Record` → `DnsRecord`).** Cloudflare
carries SDK aliases and the proxmox state is on the v8 tokens, so a replace
means one is missing: fix it, do not apply.

### Ollama 0.40.3 + flash attention on Blackwell

[ollama/ollama#18276](https://github.com/ollama/ollama/issues/18276) (open, no
fix): on an RTX 5070 Ti (sm_120), `qwen3moe` models with flash attention on
crash at warmup in the flash-attention MMA kernel, with
`cudaFuncSetAttribute` returning "shared object initialization failed". VRAM
fits; the crash is not an out-of-memory.

This release matches the trigger exactly:

- The chart 1.88.0 bump runs Ollama **0.40.3** (image tag tracks the chart
  appVersion; the repo sets no tag).
- `OLLAMA_FLASH_ATTENTION=1` is forced on, not `auto` (`389f4a7`).
- The executor base is Qwen3-Coder-30B-A3B, a `qwen3moe` model, on the same
  sm_120 GPU.

**It is not confirmed broken here.** The report is Windows on 0.33.3, and it
may be a driver problem: the Windows CUDA 13 build JIT-compiles PTX. Another
user reports 0.40.1 working. The cluster runs Linux, has used flash attention
on 0.32.9 since August without issue, and gets a new NVIDIA driver from Talos
1.14 in the same release.

Roll the Ollama chart after Talos has settled, so that a crash points at one
change, not two. Check with:

```bash
kubectl exec -n ollama deploy/ollama -- ollama run executor 'hello'
kubectl logs -n ollama deploy/ollama | grep -i -E 'shared object|flash|panic'
```

If it crashes, either:

- set `OLLAMA_FLASH_ATTENTION=0` and drop `OLLAMA_KV_CACHE_TYPE`, which needs
  flash attention. An f16 KV cache at `num_ctx` 14336 costs about 1.4 GB of
  the 2.5 GB headroom, so it still fits. Or
- hold the chart at 1.74.0.

### Falco 0.43.1 on Linux 6.18.53+

Talos 1.14.4 ships Linux 6.18.57. From 6.18.53 (kernel commit `77515ab12e49`)
the Falco 0.43.1 `modern_ebpf` `signal_deliver` program fails to load with
EACCES (-13), so Falco crashloops on every node from the first Talos upgrade.
Falco 0.45.1 (chart 9.2.1, libs 0.26.1) carries the fix
([falcosecurity/libs#3119](https://github.com/falcosecurity/libs/pull/3119),
[falcosecurity/falco#4017](https://github.com/falcosecurity/falco/issues/4017)).
No values change is needed. Step 6 syncs it early to shorten the gap.

### Harbor admin password

`existingSecretAdminPassword` sets only Harbor's initial admin password. An
existing install keeps its current one, so rotate it from the portal or API
and then update OpenBao. See "Rotating the Admin Password" in the Harbor docs.
